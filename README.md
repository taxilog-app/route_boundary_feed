# route_boundary_feed

タクシー運行アプリ（route_timer_app）の**丁目境界レイヤ**用データ配信ハブ。
営業圏ごとにフォルダを分け、GitHub Pages で静的配信する。

- `fukuoka/` … 福岡交通圏
- `tokyo23/` … 東京特別区・武三交通圏（東京23区＋武蔵野市＋三鷹市）
- `osaka/` … 大阪地区（運賃ブロック＝大阪府全域。丁目8,924／町枠4,041／区界73）
- `nagoya/` … 名古屋交通圏（32市区町村。丁目6,748／町枠3,517／区界32）

各フォルダに `choume_fill.geojson`（丁目・塗り）、`machi_frame.geojson`（町枠）、
`ward_frame.geojson`（区市の外周）。

ふりがな(`k`)の付与率は 福岡71.8% / 東京 / 大阪72.9% / 名古屋66.9%（元データの収録範囲による）。
郵便番号データの取得先は **https://www.post.japanpost.jp/service/search/zipcode/download/kogaki/zip/<県>.zip**
（案内ページは旧 `/zipcode/dl/…` から新パスへリダイレクトする。zipへのリンクが相対パスなので
旧パスを基準に組むと404になるだけで、ボット遮断ではない）。
**必ず kogaki（小書き）版**を使うこと＝促音・拗音が「はっちょう」と正しく出る。
大書き(oogaki)版だと「はつちよう」になる。
出典：政府統計の総合窓口(e-Stat)（https://www.e-stat.go.jp/）
「令和2年国勢調査 小地域（町丁・字等別）境界データ」（総務省統計局）を加工して作成。
表示用にポリゴンを簡略化している。境界データは統計区画のためのもので、
実際の行政界と一致しない場合がある。
町名の読み仮名は日本郵便株式会社「郵便番号データ」を加工して作成。

## `pref/{都道府県コード}/` … 全国の逆ジオコーディング用（2026-07-25 追加）

座標→住所（例: 大阪駅→「大阪市北区梅田三丁目」）をアプリ内で解くためのデータ。
運転手は自分の営業圏の1県ぶんだけ取得して端末にキャッシュする。

- `choume_fill.geojson` … 丁目ポリゴン（`n`=町名+丁目, `b`=bbox）
- `chome_ward.json` … 各丁目の市区町村名（ポリゴンと同順・同件数の配列）

47都道府県・231,370丁目（1県あたり1.5〜13.7MB、gzip で概ね1/5）。

上の `fukuoka/` `tokyo23/` は地図表示用（町枠つき・交通圏のみ）で用途が別。
こちらは表示用プロパティを落とし、県まるごとを収録している。

生成手順は route_timer_app の `tools/build_choume_boundary_pref.sh`。
表示用（営業圏ごと）は `tools/build_choume_boundary_area.sh <営業圏> <県コード> [市区町村コード,…]`。
出典：政府統計の総合窓口(e-Stat)（https://www.e-stat.go.jp/）
「令和2年国勢調査 小地域（町丁・字等別）境界データ」（総務省統計局）を加工して作成。
表示用にポリゴンを簡略化している。境界データは統計区画のためのもので、
実際の行政界と一致しない場合がある。
